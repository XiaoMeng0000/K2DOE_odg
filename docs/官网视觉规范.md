# 官网视觉规范(KSP2 Design Language)

> 适用版本:官网三页改版(首页 / 版本动态 / 上手指南)之后
> 本文档固化官网站点的**视觉与结构决策**,与游戏本体 `docs/UI面板视觉风格规范.md` 同源:
> 游戏内是**高密度仪器界面**,官网是**有呼吸感的展示页**,两者共用同一套色彩与组件语汇。

---

## 一、总设计原则

1. **一套视觉语言**:官网与游戏使用同一组色板与组件语汇,玩家从官网进入游戏不应感到换了产品。
2. **明度分层代替发光**:层级靠"面板底 → 内容底 → 深底卡"的三级明度差表达;界面元素一律**不加霓虹发光**。
3. **紫头条标识分区**:卡片头、列表头、折叠面板头统一使用紫色头条(`--theme-btn-selected`),这是本作视觉语言的标志性元素。
4. **细描边,不用虚线**:分隔一律 1px 实线;禁止 `dashed` 边框(旧版每块都用虚线,是"AI 感"的主要来源之一)。
5. **数据用等宽,正文用系统字体**:版本号、日期、键位、编号、坐标一律等宽字体;正文与标题使用系统无衬线,保证中文阅读舒适。
6. **颜色唯一来源**:所有色值只允许出现在 `css/main.css` 的 `:root` 变量中,新增色值先加变量再使用。

## 二、色彩变量(唯一真源:`css/main.css :root`)

### 2.1 面板明度分层(取自游戏本体 `theme.css`)

| 变量 | 值 | 用途 |
|------|----|------|
| `--theme-bg` | `#2E3540` | 面板壳(最浅,本官网暂未大量使用,留给"外框面板") |
| `--theme-panel` | `#1C212A` | 内容区底:卡片、表格、折叠面板 |
| `--theme-panel-deep` | `#14191F` | 更深底:嵌套卡、表格隔行、hover 后的卡片 |
| `--theme-hover` | `#0B0E13` | 行 hover 底 |
| `--theme-btn-selected` | `#4852AF` | **紫头条** / 选中态 / 主按钮底 |
| `--theme-active-bg` | `rgba(80,80,160,0.28)` | 导航与按钮的悬停高亮 |

### 2.2 描边

| 变量 | 值 | 用途 |

## 三、字体

| 变量 | 字体栈 | 用途 |
|------|--------|------|
| `--font-body` | `PingFang SC / HarmonyOS Sans SC / Microsoft YaHei / system-ui` | 标题、正文、按钮 |
| `--font-mono` | `ui-monospace / Cascadia Mono / Consolas` | 版本号、日期、键位、编号、角标、数据行 |

**约定**:不引入任何外部字体 CDN(旧版依赖 Google Fonts,国内加载慢且构成额外失败点)。

## 四、组件规范

| 组件 | 结构 | 规则 |
|------|------|------|
| 顶栏 | 深底半透明 + 底部细描边 | 导航当前页用紫底高亮;语言按钮为描边小按钮 |
| 板块头 `.section-head` | 标题(左) + 角标(右) + 底部 1px 描边 | 标题 600 字重、1.45rem;**禁止装饰性前缀**(`##`、`//` 已移除) |
| 图文特性行 `.feature-row` | 左图右文交替 | 图片容器 16:9 + 深底 + 细描边 + 4px 圆角 |
| 文字卡 `.feature-card` | **紫头条**(编号) + 标题 + 副标 + 描述 | 两列网格;900px 以下转单列 |
| 版本卡 `.update-card` | **紫头条**(版本号 + 日期) + 标题 + 要点 | 时间线按版本倒序;首页只显示最新 3 条 |
| 状态条目 `.notices-list li` | 深底 + 左侧 2px 数据色条 | 编号用等宽 `[01]` |
| 折叠声明 `.legal-fold` | **紫头条**(标题 + 提示) + 展开内容 | 版权等长文本一律默认折叠 |
| 联系人卡 `.contact-card` | 顶部 2px 紫条 + 徽章 + 值 + 复制按钮 | 复制按钮为描边小按钮 |
| 步骤卡 `.step-card` | **紫头条**(编号) + 标题 + 正文 | 上手指南专用,两列 |
| 键位表 `.key-table` | 面板 + 隔行深底 + 行分隔线 | 键名等宽并用数据色 |
| FAQ `.faq-item` | `<details>` + 右上 `+ / −` | 默认收起 |
| 按钮 `.cta-btn` | 主按钮紫底白字;次级为描边 | 禁止发光与渐变 |

## 五、页面结构(三页)

| 页面 | 定位 | 内容 |
|------|------|------|
| `index.html` | 门面 | Hero(版本状态 + 立即试玩 + 技术规格行)、游戏简介、玩法特色(3 图文 + 4 文字卡)、版本动态**最新 3 条** + 查看全部、联系我们、版权折叠 |
| `news.html` | 档案 | 完整版本时间线(全部版本)、版本状态(已知问题)、去玩最新版 |
| `guide.html` | 上手 | 开始游戏四步、常用键位表、常见问题、去玩最新版 |

**分流原则**:会随时间无限增长的内容(更新记录、已知问题)**不进首页**;首页只保留"是什么、多好玩、怎么开始"。

## 六、维护规则(发版同步清单)

游戏本体每发布一个版本,官网需要同步以下 4 处:

1. `src/config/site-config.js` —— `version`(最新正式版)、`devVersion`(开发中版本,无则置空)
2. `src/config/content-zh.js` / `content-en.js` → `updates.entries` —— 在"近期动态"之后插入新版本条目(版本号、日期、3–5 条要点摘要)
3. 同上 → `notices.items` —— 更新"最新正式版"编号与该版本新增的已知问题
4. 同上 → `features.items` —— 若该版本带来**新玩法系统**,补一张玩法卡(无截图即为文字卡)

其余文案(简介、指南、FAQ)按需更新。中英两份文案**结构必须同构**,新增字段两份都要加。

---

## 七、部署与验证

1. 本地预览:`node dev-server.mjs 8000` → 打开 `http://127.0.0.1:8000/`
2. 三页检查:首页 / `news.html` / `guide.html`,并在两页之间跳转验证**语言偏好跨页保持**
3. 窄屏检查:窗口缩至 900px 与 640px,确认图文行、文字卡矩阵、键位表正常堆叠
4. 提交推送后 GitHub Pages 自动部署(Actions:Deploy Jekyll with GitHub Pages)

---

## 八、禁止事项

- ❌ 霓虹发光(`text-shadow` / `box-shadow` 光晕)—— 层级一律用明度与描边表达
- ❌ 虚线分隔(`border: dashed`)
- ❌ 装饰性前缀(`##`、`//`、`>>>` 等无信息量的符号)
- ❌ 外部字体/图标 CDN 依赖
- ❌ 在业务代码中硬编码色值(必须走 `:root` 变量)
- ❌ 把长文本(版权、完整更新记录)堆在首页

---

> 本规范随官网结构演进更新;第二章(色彩变量)与第八章(禁止事项)为最高优先级,新增组件前务必对照。
