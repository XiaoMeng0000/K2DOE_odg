**参考站解法**:R3(NMS)与 R2(Factorio)在同类版式中都把两侧内容**垂直居中**,并用"等宽短行 + 2 行说明"限制文字列高度;**本条与我方实际情况不一致**。

**判定**:**不必改结构**。若仍要压缩留白,最小手段是给 `.feature-copy` 增加 `justify-content: center` 上限并补充信息密度(例如加一行 `.feature-meta` 元信息),而不是改网格。

## 六、未证实项与风险

### 6.1 未证实项(明确不是观察结论)

1. **Astroneer 官网的实际视觉设计未知**。只证实了 `.loader`(z-index 99999)未淡出、视觉内容被永久遮住;其正文样式未取得画面证据。文中不引用其任何视觉特征(只把它当"JS 依赖首屏"的反面案例)。
2. **KSP 官网首屏画面未知**。首屏为自动播放视频,截图得到近黑画面;可读的只有中下部三张并列条目。**未证实**其首屏文字层级与布局细节,故 R1 的借鉴点只取中下部可观察部分。
3. **R5 Grafana 的截图像素层不完全可信**。该页截图的重影/错位表明渲染未收敛(页脚与主截图纵向被轻微拉伸),因此 R5 的结构结论全部来自 `browser_a11y` 语义树(节点 18/20 的主-次按钮并列),而非像素观察。
4. **动效时长与缓动曲线不可复现**。我方未对任何参考站的动效做帧级采样;文中未给出任何动效时长建议。现有 `.reveal`(0.6s)与 `hero-in`(0.7s)节奏来自我方代码本身,不是参考站结论。
5. **NASA Eyes 主界面未观察到**。两次截图均在 `LOADING` 态(第二次进度条右移,证明真在推进)。因此 R7 的借鉴点仅限**加载态**;其轨道/导航球交互界面(是否用双层描边、如何画轨道)未证实,第五节 ③ 的画法依据是**本体规范 §3.8**,不是 NASA 画面。
6. **`--accent #88ccff` 与 `--progress-green #3dff3d` 引入官网后的可读性未实测**。这两个值是本体规范 §2.3 的定义,本次未做对比度测试;若要作为文字色使用,应先测 WCAG 对比度再定。
7. **`position: sticky` chip 行的行为未实测**。`html { scroll-behavior: smooth }`(main.css:60)与 sticky 组合在窄屏下的表现未验证。
8. **各镜面/替代站的可行性未验证**。文中每站只给了 1 个本轮实际访问成功的 URL;未验证是否存在更稳定的替代入口。
9. **Raspberry Pi 软件页(`07-raspberrypi.png`)可读但未计入正式清单**。它是通用下载页而非同类游戏/数据可视化站,其主视觉为高饱和品红大色块(与深空 HUD 语汇无关),只有"CTA + 文档链接并列"一点与我方相关,而该点已由 R5(Grafana)覆盖,故只作为备选证据留档、不占用清单名额。

1. **文档冲突(已知,不自行裁定,已上报组长)**:本体规范 **§3.2** 要求"分区标题(非头)用 `// ` 前缀 + `--accent` 蓝";官网规范 **§八 第 3 条 / §四** 把 `//` 列为禁止项。两份规范都自称同源。**本文件所有落点建议一律不使用 `//` 前缀**,冲突本身留待总监裁定。
